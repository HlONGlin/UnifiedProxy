# 舰队管理使用指南

舰队主机提供一个网页，集中管理多台子服务器。子服务器运行代理与节点进程；入站、用户、出口和路由都在主机网页配置。

## 统一登录与独立工作台

只需在主机登录一次。登录后首先显示独立的舰队管理页，每台子服务器有自己的卡片；点击卡片名称、卡片空白处或“管理节点”，直接进入该服务器的**仪表盘**。待接入卡片的主按钮仍可获取安装命令，卡片名称可提前打开配置工作台。

每台服务器的工作台有独立网址，地址中的节点 ID 决定当前服务器。可以同时打开多个标签页，分别管理不同服务器；刷新会保留当前服务器和功能页。顶部持续显示服务器名称、在线状态、地址与最近心跳，点击“返回舰队”回到服务器列表。会话到期时统一回到原登录页，完成登录后返回所访问的服务器；退出登录对所有工作台生效。

例如管理员面板位于 `/admin/`：

| 地址 | 用途 |
|---|---|
| `/admin/` | 独立舰队入口：服务器卡片、任务、聚合订阅、完整备份和主机维护 |
| `/admin/nodes/<节点ID>/` | 当前服务器仪表盘；可管理该服务器入站、用户、出口、路由、连接、日志和配置 |
| `/admin/host/#settings` | 主机账号、面板设置与共享默认配置 |

节点工作台中的修改只发布到当前服务器。CPU、内存、磁盘、运行时间、速度、连接与日志来自该节点的签名上报；离线时显示最近一次数据与最后心跳，不使用主机统计填补。CPU 历史随节点上报更新。上报的连接明细最多 200 条、日志最多 300 条，避免大型状态报文拖慢心跳；总连接数仍根据完整快照计算。旧节点尚未上报的新指标显示为空，升级节点后补齐。

节点分享链接使用该子服务器的有效公网地址。用户订阅仍由主机提供，工作台只列出当前服务器用户的订阅入口；同用户名的跨服务器聚合规则保持原有行为。订阅模板为主机共享资源，统一账号和面板配置在“主机设置”管理。

入站、用户、出口、路由和确认弹窗使用半透明深色遮罩，原页面保留在背景中，五套配色的明暗模式共用此规则。

## 接入第一台子服务器

1. 登录主机后进入“舰队管理”，点击“添加子服务器”。
2. 填写容易辨认的名称，例如“香港入口”；**子服务器公网地址可留空**，接入后自动识别。需要指定域名或特定 IP 时再填写，用于生成客户端连接地址。
3. 点击“创建并获取接入命令”。卡片立即出现，状态为“待接入”。
4. 在弹窗确认**主机公网地址**，可直接填写子服务器能够访问的 `http://主机IP:端口`，也支持 HTTPS。这里不附加管理员面板路径；反向代理需转发 `/fleet/v1/`。HTTP 无需证书，按当前面板地址生成命令。
5. 点击“复制一键接入命令”，在 Linux 子服务器以 **root** 粘贴整条命令并回车。命令已经包含脚本链接、主机信息和一次性 token，自动下载并校验节点程序，安装缺失的 Mihomo，绑定当前卡片并启动服务；无需再粘贴 token 或手动重启。
6. 回到主机等待状态刷新，通常不超过 15 秒。在线后点击“管理节点”，进入该服务器仪表盘，再从侧栏打开“入站列表”或“Mihomo 设置”。

一键接入参考 UnifiedProxy v1.6.3 的“卡片生成命令、子主机执行后自动上线”流程，使用现有一次性令牌和签名身份。适用于运行 systemd 的 Linux；执行命令需要 Bash、curl 和 root。Debian/Ubuntu 或 RHEL 系可自动补齐缺少的工具。程序默认位于 `/usr/local/unifiedproxy-node/node`、数据位于 `/usr/local/unifiedproxy-node/data`；新安装的节点管理端口只监听回环地址，日常操作都在主机网页完成。

例如主机面板为 `http://203.0.113.10:2053/admin/`，接入地址填写 `http://203.0.113.10:2053`。节点安装、签名接入、配置领取及独立心跳均支持 HTTP；公网 IP、局域网 IP、域名均可。HTTP 不加密传输，使用 HTTPS 可加密脚本下载及节点通信；HTTPS 脚本下载不允许降级到 HTTP。两种方式均保留公钥校验和防重放，但签名不能为 HTTP 下载的安装脚本提供传输保护。节点及 Mihomo 发布包仍通过 HTTPS 下载并校验 SHA256。

脚本由当前主机的 `/fleet/v1/install.sh` 提供，不在下载 URL 中包含 token。正式主机优先安装与自身一致的节点版本；开发版本使用最新正式版。节点程序按发布校验和校验；缺少 Mihomo 时安装固定的 v1.19.33 并核对上游 SHA256。保留现有可用内核；已有配置在安装前备份，账号、入站和路径保留。同一卡片重复执行只重启现有服务；已绑定到其他卡片或主机时停止，需先明确退出或重绑，避免覆盖原有身份。紧急接管期间不会自动恢复托管。

创建卡片后仍需自己打开子服务器终端执行命令，网页不会登录 SSH。Docker 或自定义目录请展开“已安装节点 / Docker：手动接入”，使用已包含 token 的手动命令，按实际路径调整，并重启节点容器或进程。安装和手动接入示例见[运行与迁移指南](unifiedproxy-migration.md#接入)。

令牌有效期 15 分钟，仅用一次，命令通过标准输入交给节点程序，token 不出现在下载 URL、节点进程参数或 systemd 服务文件中。**复制的整条命令本身包含 token，可能保留在 shell 历史中，请勿公开分享。** 过期时复制按钮停用，关闭弹窗后重新获取；接入失败可在卡片“获取接入命令”重试，需要新 token 时选择“重新生成接入信息”。

## 看懂卡片与操作范围

| 显示或入口 | 含义 |
|---|---|
| 待接入 | 已登记卡片，还没有收到子服务器连接 |
| 在线 | 最近收到了节点上报；仍需结合代理内核和配置状态判断是否可用 |
| 离线 | 以前连接过，当前没有及时上报；不代表已运行的代理一定停止 |
| 已吊销 | 主机已撤销该节点接入权限；已有代理进程可能继续运行 |
| 配置已同步 | 节点上报的配置版本与主机期望版本一致 |
| 等待同步 | 主机已发布新版本，等待节点领取、校验和应用 |
| 管理节点 / 卡片名称 | 直接进入该服务器独立仪表盘，共用已登录的主机会话 |
| 更多操作 → 入站与用户 | 直接打开该服务器的入站列表 |
| 更多操作 → 出口与路由 | 打开该节点的出口编辑页，可继续切换路由规则 |
| 顶部服务器信息 | 显示当前服务器名称、地址、状态与最近心跳；返回舰队可选择其他服务器 |
| 舰队页 → 主机设置 | 编辑主机账号、面板与供节点套用的全局默认设置，不在主机运行代理内核 |

卡片同时显示代理内核状态、节点版本、流量与最近心跳时间，并标注“自动识别地址”或“手动指定地址”。搜索支持名称、地址和节点 ID；点击统计卡或状态筛选可缩小列表。名称与地址必须点击“保存信息”才会保存，取消或按 Escape 会放弃本次修改。

## 关闭入站与停止内核

入站列表的“启用”开关控制当前服务器的指定入站。关闭时，主机发布新配置，子服务器移除监听并断开该入站已经建立的代理连接；其他入站和服务器继续运行。用户开关同样等待配置应用，并只清理被禁用用户的现有连接。

下发期间，开关保持不可重复点击，鼠标停留可看到“等待子服务器应用配置”；刷新列表不会提前解除等待。子服务器执行成功后才提示已启用或已禁用。离线、执行失败或超时会显示对应提示，可在“舰队 → 任务记录”查看实际结果，不能把“配置已保存”当成“节点已关闭”。

仪表盘的 Mihomo 停止按钮控制当前服务器的内核。停止状态保存在节点本地，后续保存配置、周期任务和重启节点服务均不会自动开启；点击“启动”或“重启”后恢复。管理进程继续发送心跳，因此停止内核不等于服务器离线。

**主机和子节点都需要升级至 v1.6.17。** 只升级网页无法让旧节点补做现有连接清理或保存停止状态。更新保留原有入站、用户、节点身份和数据，无需重新接入。

## 自动地址与心跳

地址处理参考 UnifiedProxy v1.6.3 的“节点主动上报、手动地址优先”行为：节点启动后在后台探测公网 IP，每 5 分钟重新探测；通过签名心跳上报，主机持久保存最近一次有效公网 IP。探测请求有超时，失败保留上次成功地址，不阻塞心跳或代理配置。没有上报地址时，主机仅以已认证连接的公网来源 IP 回退；不会信任任意 `X-Forwarded-For` 或 `X-Real-IP`。

公网地址留空时使用自动值，手动填写时优先使用人工值；在“编辑名称与地址”中清空地址并保存，就恢复自动识别。订阅和分享节点使用同一个有效地址；尚未识别地址的节点暂不加入订阅，避免错误使用主机面板地址。NAT、多网卡或需要域名证书的部署，建议手动指定客户端实际可访问的地址。

新节点每 15 秒发送独立心跳，不等待配置应用、内核更新或其他长任务，也不会用旧快照覆盖较新的配置、流量状态。主机按接收时间判断在线，90 秒未收到心跳或状态上报即显示离线；收到有效上报后恢复。登记令牌成功只代表绑定身份，收到第一条心跳或状态上报后才显示在线。离线不等于代理停止，在线也不等于内核或监听端口一定可用。

主机和子节点均更新后才能使用完整的自动探测与独立心跳。旧节点仍可按原签名协议上报状态；直连时主机可从公网连接来源识别地址，经过私网反向代理时请升级节点或手动填写。五分钟内的 IP 变化探测存在延迟，分享链接需重新获取或刷新订阅。心跳上报和网页刷新各有周期，页面显示可能比服务端记录晚一个刷新周期。

## 按任务寻找功能

| 想做什么 | 操作入口 |
|---|---|
| 添加入站、生成节点、管理用户 | 服务器卡片 → 管理节点 |
| 配置出站、出口策略与分流 | 更多操作 → 出口与路由 |
| 再次下发已有配置 | 更多操作 → 发布当前配置 |
| 批量巡检、更新 Geo、更新内核或 Agent | 勾选服务器 → 批量操作 → 选择操作 |
| 修改多台服务器的用户配额或套用主机默认 | 勾选服务器 → 批量操作 → 修改用户配额 / 应用全局默认 |
| 查看任务进度与失败原因 | 任务记录 → 最近任务 → 展开一条记录 |
| 获取用户的聚合订阅 | 用户订阅 → 读取用户订阅 → 复制订阅地址 |
| 完整备份、历史 merit.json 导入、恢复或 WebDAV | 备份与迁移 |
| 查看主机公钥、管理中央证书、更新控制端 | 主机维护 |
| 编辑完整模型、辅助服务 JSON 或创建 Sidecar | 高级配置 → 选择服务器 → 展开相应项目 |
| 撤销节点权限 | 更多操作 → 吊销接入权限 → 确认 |

普通状态采集无需参数。检测出口需要子服务器实际可用的 SOCKS5 地址；更新 Agent 需要 HTTPS 更新包和 SHA256。尚未接入或未声明相应能力的节点会显示说明，避免提交无法执行的任务。修改配额、套用配置、更新、恢复和吊销等操作需要在界面再次确认。

原始 JSON 编辑仍保留在高级折叠区，日常使用无需打开。15 秒状态轮询会更新卡片与任务结果，并保留正在填写的任务表单。

### HTTP 下点击“添加入站”没有反应

v1.6.14 的编辑页面仍直接调用仅在安全上下文提供的 `crypto.randomUUID()`；使用公网或局域网 IP 的 HTTP 面板时，该接口不可用，初始化默认用户会报错，导致入站窗口打不开。v1.6.15 统一使用随机 ID 工具：HTTPS/回环继续使用浏览器 UUID 接口，普通 HTTP 使用 `crypto.getRandomValues()` 生成 UUID v4，保留密码学随机源。入站、单个与批量用户、凭据、出口和路由共用此工具。刷新页面也会先完成舰队请求绑定，再读取当前子节点配置。

此问题只需更新提供网页的主机或独立面板到 v1.6.15，并重新加载页面；无需为这项界面修复重装子节点。编辑回归脚本使用真实登录及保存接口，覆盖 control/standalone × 非回环 HTTP/HTTPS/回环 HTTP 六种场景，检查添加入站、六种协议默认用户、单个和批量用户、刷新保留节点、出口与路由保存；不模拟浏览器 API 或后台响应。证据写入 `/workspace/dist/http-editors/`。
